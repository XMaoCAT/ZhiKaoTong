# 第一部分 · 简要说明

## 1. 一句话定位

**智考通**是一套面向高校的「考勤与教务一体化管理系统」：覆盖 **学生请假审批、课表调课、课堂签到与随人互动、违规积分** 四大业务线，提供 **PC 端 + 手机端** 双端体验，内置 **实时消息推送（SSE）** 与 **多角色审批工作流**。

## 2. 技术形态速览

| 维度 | 选型 |
| :--- | :--- |
| 后端 | Node.js + Fastify + SQLite（better-sqlite3，WAL 模式），单文件数据库零运维 |
| 前端 | **原生 ES Module JavaScript，无框架、无构建工具**，浏览器直接运行 |
| 前端架构 | **微内核 + 插件**体系：宿主壳 + 13 个可插拔业务模块 |
| 实时通信 | SSE（Server-Sent Events）三级频道广播，服务端主动推送 |
| 部署形态 | 单进程 Node 服务，`start.bat` 一键启动，端口自适应写入 `data/runtime.json` |
| 外部依赖 | 零 CDN 依赖（拼音库为本地 vendor 副本），可完全离线运行 |

## 3. 角色速览（共 6 种登录身份）

| 角色 | 登录方式 | 一句话职责 |
| :--- | :--- | :--- |
| 学生 | 9 位学号（000000001–000000100） | 请假申请、看课表、课堂签到 |
| 教师 | 教职工账号下拉（教师01–05，可动态添加） | 授课课表、发起课堂签到、加课/停课申请 |
| 教务处 | 教职工账号下拉 | 班级/学生管理走申请、专业部与教师阵营管理、调课审批 |
| 学生处 | 教职工账号下拉 | 学生班级直改、班级变更审批、违规与积分 |
| 导员 | 教职工账号下拉 | 请假审批（限绑定班级）、课堂状态查看 |
| IT管理员 | 教职工账号下拉 | 系统管理：调试端点、初始化清零、生成模拟数据 |

> 教师账号**动态可扩展**：教务处可在「教务管理→教师管理」添加任意姓名的教师，新教师立即出现在登录页下拉并可登录。

## 4. 双端说明

- **PC 端**：`http://<host>/`（默认端口见 `data/runtime.json`），13 个功能模块，完整操作能力。
- **手机端**：`http://<host>/m-dev1`（需 IT 管理员开启调试端点），手机壳视图，核心功能与 PC 同步。
- **调试端点**：`/dev1`（PC）、`/m-dev1`（手机）等端点拥有**独立登录态**，可多角色并行测试。

## 6. 五大业务流（一句话版）

1. **请假流**：学生签名提交 →（向导实时显示将耽误的课）→ 导员审批（可要求销假凭证）→ 学生销假。
2. **调课流**：教师点课表空格申请加课 / 点本人课申请停课 → 教务处审批 → 学生与教师实时收到通知。
3. **课堂流**：教师发起课堂 → 学生口令/点击签到（请假学生自动标记）→ 教师随人提问/加减分/记旷课 → 结束结算。
4. **班级变更流**：教务处提交建班/改成员/解散申请 → 学生处审批 → 生效并通知教务处。
5. **违规积分流**：课堂自动记旷课（-5）或学生处/导员手动登记（旷寝 -10）→ 低于 60 分进入预警名单 → 可走审批撤销还分。

## 2. 技术选型与设计理由

| 决策 | 理由 |
| :--- | :--- |
| **无前端框架**（原生 ESM） | 业务模块按需 import，浏览器原生懒加载；无构建链路、无版本升级负担；演示/交付环境零依赖 |
| **微内核 + 插件** | 业务功能可独立增删（物理删除零副作用已实测：删模块仅 warn 侧栏自动隐藏）；宿主只管壳与装配，业务演进不碰核心 |
| **SQLite（better-sqlite3）+ WAL** | 单文件零运维；WAL 读写并发性能好；同步 API 代码直观（事务即函数调用） |
| **SSE 而非 WebSocket** | 单向服务端推送场景足够；HTTP 原生、代理友好、自动重连（EventSource 内置）；无需额外协议层 |
| **身份头而非 Session/Cookie** | 无状态鉴权（`x-zkt-role`/`x-zkt-name`，URI 编码传中文）；调试端点天然多身份并存；SSE 场景以 query 参数兼容 |
| **单源常量（禁副本）** | 角色/守卫/教师账号/请假类型等字典全部一处定义（`consts.js`/`teachers 表`/`roles.js`），多处引用零漂移 |

## 3. 前端微内核插件架构

### 3.1 宿主（`public/index.html` + `core/main.js`）
- 纯插槽壳：页面只有 4 个挂载点——`#loginStage`（登录页）、`#topbar`（顶栏）、`#mainViewContent`（PC 主区）、`#mobileStage`（手机台）。
- 启动序列：`loadRegistry()` → 调试端点开关检查 → **旧会话迁移**（历史"教务科"→"教务处"）→ 会话判定 → 恢复工作区 / 显示登录页。
- 登录成功后：宿主保存身份（localStorage，按端点独立键）、渲染侧栏（按角色过滤）、挂载角色默认首页、**建立宿主级 SSE 单连接**（模块反复挂卸不会反复建断连接）。

### 3.2 插件加载器（`core/plugin-loader.js`）
- 模块四件套：`manifest.json`（元数据+权限声明）/ `index.js`（mount/unmount 生命周期）/ `style.css`（私有样式）/ `DEV_LOG.md`（交接日志）。
- **三重校验**：`enabled === true` → `platforms` 含当前端（pc/mobile）→ `allowedUserGroups` 含当前角色（未登录仅放行显式含 `guest` 的登录模块）。
- **熔断隔离**：每个模块独立 try/catch——404、语法错误、挂载异常仅 `console.warn` 跳过，绝不拖垮宿主与其他模块。
- **懒加载**：模块 JS/CSS 均在首次挂载时动态 import/注入，卸载时移除样式 link。
- **注册表**：`modules/registry.json` 列出 13 个启用模块；新模块放入目录并登记即完成接入。

### 3.3 事件总线（`core/event-bus.js`）
- CustomEvent 封装的进程内 pub/sub（on/off/emit，无监听方时发送方静默）。
- 承担两类通信：**模块 ↔ 宿主**（`auth:logged-in`、`nav:goto-module`、`ui:toast`、`ui:open-modal` 等）与**模块 ↔ 模块**（`leave:submitted`→导员列表刷新等）。
- 所有 SSE 服务端事件由共享件 `shared/sse.js` 统一转发为 `sse:xxx` 总线事件，模块各自订阅、卸载时解绑。

### 3.4 共享件层（`public/shared/`）
跨模块复用、严禁复制副本：`roles.js`（角色常量+会话+群组映射）、`leave-wizard.js`（请假向导/签名板/滚轮时间/审批弹窗）、`sse.js`（SSE 转发）、`timetable.js`（课表渲染组件）、`pinyin-util.js`（拼音搜索）、8 个 `api-*.js`（REST 客户端，统一 URI 编码头与错误处理）。

### 3.5 双端复用策略
- 同一模块体系按 `platforms` 字段分流：PC 模块挂 `#mainViewContent`，手机端为单一 `mod-mobile-home` 大模块内部再分视图（首页/请假/教务/课程/课堂/学生处/调课审批/课堂记录/我的）。
- 弹窗、课表、审批列表等 UI 件全部下沉宿主全局样式或共享件——**双端同步铁律**：任何业务功能必须同时落地两端。

## 4. 后端架构（`server.js` + `src/`）

### 4.1 路由组织
- `server.js`：Fastify 实例、静态托管、端口探测（占用自动顺延）写入 `data/runtime.json`、调试端点路由（`/devN`、`/m-devN` 注入独立 localStorage 前缀）、优雅停机端点。
- `src/api/` 10 个路由文件各自导出 `registerXxxRoutes(app)`，按业务域拆分：
  `leaves`（请假状态机）/ `academic`（学生班级教师）/ `workflow`（审批引擎）/ `majors`（专业部）/ `timetable`（课表与耽误课）/ `classroom`（课堂）/ `violations`（违规积分）/ `events-global`（SSE 端点）/ `admin-data`（初始化与模拟数据）。

### 4.2 单源核心（`src/core/`）
| 文件 | 职责 |
| :--- | :--- |
| `db.js` | better-sqlite3 连接 + WAL + 系统表建表 + `now()` |
| `config.js` | 配置读取 + **配置文件热更新**（fs.watch，改 config.json 免重启） |
| `consts.js` | 工作流角色常量（REQUEST_ROLES/REVIEW_ROLES）单源 |
| `http-utils.js` | `readRole/readName` 身份头读取（header 优先、query 兜底，全项目唯一实现） |
| `pub.js` | SSE 发布池（详见第三部分 §7） |

### 4.3 守卫矩阵（权限的单一真相）
每个写端点调用守卫函数，常量集中定义：
```
READ_ROLES      = [教务处, 学生处, IT管理员]   → 读学生/班级/教师数据
WRITE_ROLES     = [学生处, IT管理员]           → 直改班级与学生（教务处写操作一律走申请→学生处审批）
TEACHER_ADMIN   = [教务处, IT管理员]           → 添加教师/授课分配/专业部/导员绑定
REQUEST_ROLES   = [教务处]                    → 提交班级变更申请
REVIEW_ROLES    = [学生处, IT管理员]          → 审批班级变更申请
```
**前后端双保险**：前端 manifest `allowedUserGroups` + 侧栏 ROLE_ACCESS 过滤（体验层），后端守卫矩阵（安全层）——绕过前端直调 API 仍被拦截。

### 4.4 数据模型（17 张业务表 + 4 张系统表）

```
组织维度                          课堂维度
─────────                         ─────────
major_departments 专业部           lesson_sessions  课堂会话(open/ended)
  ↑ classes.major_id                ↑ session_id
classes 班级                       sign_records     签到(UNIQUE session+student)
  ↑ students.class_id              classroom_events 课堂事件流(加减分/旷课/随人/撤销/状态覆盖)
students 学生(100,含score积分)      ↑ session_id
teachers 教师账号(动态)             violation_records 违规流水(旷课-5/旷寝-10)
teacher_classes 教师↔授课班级       ↑ student_id/session_id
teacher_majors   教师↔专业部(多对多)
counselor_classes 导员↔绑定班级     审批与通知
                                   ─────────
请假业务                           workflow_requests 申请(7类/4状态/audience审批方)
─────────                         notifications     通知(role/class/teacher 三类受众)
leaves 请假(状态机/签名/凭证/销假)  ↑ request_id

```

关键约束：`sign_records` 唯一键防重复签到；`workflow_requests.status` CHECK 约束（pending/approved/rejected/withdrawn）；`timetable_lessons` 双源一表（base 周课 + add 单次课，`cancelled` 停课留痕不删除）。

## 5. 实时通信设计（SSE 三级频道）

```
浏览器 EventSource(/api/events/global?role=&name=)
        │ 首帧 hello {channels:[...], serverTime}
        ▼
服务端 pub.js 发布池
  channels:  role:<角色>      ← 全体同角色
             class:<班级id>   ← 该班学生（按 students.class_id 自动挂入）
             teacher:<账号>   ← 指定教师
  心跳: 每 15s ": ping" 保活；写失败连接静默移除
```
- **发布原语**：`publishToRole / publishToClass / publishToTeacher`，事件帧 `event: <名>\ndata: <json>\n\n`。
- **身份通道**：EventSource 不能带自定义头 → 登录时以 query 传身份，服务端 `http-utils` 双通道读取。
- **前端转发**：宿主级单连接收帧 → eventBus 派发 `sse:xxx` → 订阅模块刷新界面。
- **离线兜底**：通知同时落 `notifications` 表，模块挂载时补拉未读（SSE 断连期间错过的消息不丢）。

## 6. 质量保障体系（项目内建铁律）

| 铁律 | 内容 |
| :--- | :--- |
| 零空话原则 | 界面只放真实可操作控件，无功能的说明卡一律不渲染 |
| 双端同步 | 任何业务功能必须同时落地 PC 与手机端 |
| 单源禁令 | 字典/守卫/工具函数严禁多处副本（历史踩坑促成） |
| 物理删除零副作用 | 删模块目录仅 warn，界面自动回落不报错 |
| UI 审查 SOP | UI 变更收尾必做截图审查 + computed 样式核验（computed 为事实源） |
| manifest 完整性 | 必含 entry+style 双字段（缺 style 导致零私有样式裸排） |
| 弹窗样式归宿主 | 弹窗可能被任意模块打开，其内样式必须全局 |
| 定时器必清理 | 所有 interval（红线/轮询/动画）随模块卸载销毁 |

# 第三部分 · 动态计算与核心机制详解

## 1. 课表渲染：分钟级连续定位算法（`shared/timetable.js`）

**问题**：课程时间任意（08:00–09:40），不能用"第 N 节"离散格子。
**方案**：将 06:00–22:00（360–1320 分钟，共 960 分钟）映射为 0–100% 连续区间：

```
top    = (开始分钟 - 360) / 960 × 100%     ← 课程卡片顶部
height = (结束分钟 - 开始分钟) / 960 × 100% ← 卡片高度
```
- 相邻课程视觉间距即时长差；越界自动钳制（`Math.max/min` 裁剪到边界）。
- **当前时间红线**：`(now - 360) / 960 × 100%`，仅渲染在"今日列"；组件内置 30s `setInterval` 重算重绘（模块卸载时 `handle.destroy()` 清定时器）。
- **"正在上课"判定**：`列=今天 && now ≥ 开始 && now < 结束 && 未停课` → 蓝色描边高亮。
- **午休分隔线**：`(720 - 360) / 960 = 37.5%`。
- **组件契约**：`renderTimetable(容器, 课表数据, {compact, onCellClick, onLessonClick})` 返回 `{refresh, setMode, destroy}`——PC 周视图、手机端 compact（内层 640px 横向滚动）共用同一实现。

## 2. 耽误课计算：逐日展开 + 双源命中（后端 `timetable.js` `affectedLessons`）

学生请假向导 Step2 与导员审批弹窗共用**后端单源函数**（防前端时区分叉）：

```
输入：studentId + 请假起止（dateFrom/timeFrom/dateTo/timeTo）
① 查学生所在班级 → 取该班全部未停课课程
② 逐日循环展开请假区间（含首尾日，guard 计数防死循环上限 400 天）
   每天：
   - 日期字符串用【本地时区】手工格式化（getFullYear/getMonth/getDate）
     ⚠ 不能用 toISOString()——它走 UTC，东八区会比本地早一天，导致"周一申请显示周日"
   - weekday = getDay()（0 归一为 7）
   - 首日从请假开始时刻起、末日到结束时刻止（中间日 0:00–24:00）
③ 命中判定：
   - 周课(base)：course.weekday === 当天weekday
   - 单次课(add)：course.single_date === 当天日期
   - 且时段相交：dayStart < 课程结束 && 课程开始 < dayEnd
④ 输出清单：课程/教师/日期/星期/时段/来源（供前端直接渲染）
```

## 3. 加课冲突检测：预检 + 复检双层防线（`checkConflict`）

**同一函数**同时服务于申请提交时的 validator（预检）与审批时的 executor（复检）：

```
候选冲突集 = 同班 OR 同教师 的未停课课程
           且 weekday 相同 且 (base课 OR single_date 相同)
判定相交：新开始 < 已结束 && 已开始 < 新结束
```
- **预检（400）**：提交即拦截，提示"时段冲突：与《课程》（时段）重叠"。
- **复检（409）**：审批事务内再查——若 pending 期间该时段已被其他先批准的申请占用，抛出"审批期间时段已被占用，建议驳回"（已实测两个同时段申请先后审批的场景）。

## 4. 审批工作流引擎：策略表 + 事务 + 并发互斥（`workflow.js`）

**七类申请**统一由 `TYPE_HANDLERS` 策略表驱动，每类声明五要素：

```
TYPE_HANDLERS[type] = {
  submitterRoles: 谁能提交,
  approverRole:   谁来审批（audience）,
  title/detail:   申请标题与展开细则（供列表/弹窗渲染）,
  validate:       提交时校验（400）,
  execute:        同意时的业务执行（在事务内调用）,
  notifyApproved: 批准后向谁发什么通知（如班级新课通知）,
}
```
七类申请：`class-create / class-edit / class-dissolve`（教务处→学生处）、`add-lesson / teacher-leave / absence-cancel`（教师→教务处）、`record-modify`（教务处→教师，确认制）。

**审批原子性（防并发双击/两人同审）**：
```
BEGIN TRANSACTION
  UPDATE workflow_requests SET status='approved' WHERE id=? AND status='pending'
  ↑ 受影响行数 = 0 → 说明已被处理 → 抛错回滚（409）
  execute(业务执行：建班/改成员/写课表/停课/还分……)
  回填 result 快照
COMMIT
```
**驳回必填理由**（400 拦截）；**撤回**仅发起人 + pending（409 拦截重复/非 pending）。
**事务单源**：旷课还分（`revokeViolation`）只存在于 violations.js 一份实现，absence-cancel 与 record-modify 执行器统一调用——扣分/还分与违规行永远同事务。

## 5. 违规积分：双通道登记 + 事务一致性

```
扣分：applyViolation({studentId, type, source, session})
      事务：INSERT violation_records + UPDATE students.score += points（负值即扣）
还分：revokeViolation(violationId)
      事务：UPDATE cancelled=1 + UPDATE students.score -= points（减负数=还）
常量：POINTS = {旷课: -5, 旷寝: -10}；WARN_BELOW = 60（单源导出前后端共用）
```
- 登记通道①**课堂自动**：教师记旷课（事务内同时写 sign_records.absent + classroom_events 留痕）；②**手动**：学生处/导员登记（导员限绑定班级）。
- 低分名单/汇总均 SQL 聚合（`score < 60`、各班 AVG/违规 COUNT）实时计算，不存冗余字段。

## 6. 课堂状态机与随人/轮询

**课堂状态机**：`open →（结束 absent 快照）→ ended`；结束时未签到未请假学生批量写 `absent`，同时向导员/教务处频道推送结束事件。

**随人轮换动画**（纯前端定时器）：
```
点击「开始随机」
 → setInterval 80ms：随机一头像加 .pulse 类（其余移除）
 → Date.now() - start > 3000 → clearInterval + 定格 .picked
 → 350ms 后弹结果浮层（±1/±2/仅记录 chips）
```
动画 interval 与模块轮询分离，均带结束/卸载清理路径。

**课堂面板轮询**：进行中课堂每 3s `fetchSession` 拉取最新三类名单+计数（学生签到即时可见）；模块卸载 clearInterval；**刷新恢复**：重新挂载时查本人 open 课堂自动重建面板并恢复轮询。

**签到口令**：code 模式生成 1000–9999 随机 4 位（教师可自定义）；学生提交口令服务端比对（400 错误提示）；`sign_records` 唯一键保证一人一签，重复签到 409。**请假预置**：发起课堂时事务内查该班 approved/completed 请假与当日时段相交学生，预写 `leave` 状态（签到卡显示"请假中，无需签到"）。

## 7. SSE 发布池实现（`src/core/pub.js`）

connections: Map<res, {hbTimer, channels}>

register(res, channels)  → 幂等（重复注册先注销）+ 启动 15s 心跳
publish(channel, event, data)
